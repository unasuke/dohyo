# ゾーンファイルの書き方

dohyo は、BIND 形式のゾーンファイル 1 つから 1 つのゾーンを答えます。ゾーンファイルを読むのは、起動時、`dohyo --check`、`SIGHUP` による再読み込みのときです。下の検査のどれかに引っかかると、ファイル全体が拒否されます。起動時なら dohyo は起動せず、再読み込みなら読み込み済みのゾーンで答え続けます。

完全な例は [`examples/sub.example.com.zone`](../examples/sub.example.com.zone) にあります。

## 書けるレコード型

書けるのは次の型だけです。

| 型 | 置ける場所 | 備考 |
| --- | --- | --- |
| SOA | 頂点だけ | ファイル全体でちょうど 1 つ |
| NS | 頂点だけ | 1 つ以上。親ゾーンの委任と同じ名前にする |
| A | どの名前でも | |
| AAAA | どの名前でも | |
| HTTPS | どの名前でも | 下を参照 |

これ以外の型（CNAME、MX、TXT、CAA など）はエラーです。頂点より下の NS（委任）と、ワイルドカードの名前（`*.sub.example.com.`）もエラーになります。

存在する名前への、持っていない型の問い合わせには空の回答（NODATA）を、存在しない名前には NXDOMAIN を返します。下にレコードがあるだけの名前（`x.y` にだけレコードがあるときの `y`）も、存在する名前として扱います。

## 指示

- `$ORIGIN` は必須で、設定の `zone.origin` と一致しなければなりません。`$ORIGIN` が無いと、相対名がルートからの名前として解決されてしまうためです。最初の `$ORIGIN` より前に書いた名前はゾーンの外の名前になり、拒否されます。
- `$TTL` には秒の数だけを書きます（`$TTL 3600` と書き、`$TTL 1h` とは書かない）。dohyo が使うパーサは `$TTL 1h` を 1 秒と読んでしまうので、`$TTL` での単位は拒否します。レコードごとの TTL の欄の単位（`www 1h IN A …`）は正しく読めます。

## TTL

TTL は 0〜2147483647 秒です。同じ名前と型のレコードで TTL が食い違うときは、いちばん小さい値にそろえ、警告のログを出します。

否定応答（NODATA と NXDOMAIN）がキャッシュされる時間は、SOA 自身の TTL と SOA の MINIMUM の小さいほうです。

## HTTPS レコード

ServiceMode（priority が 1 以上）と AliasMode（priority が 0）の両方を書けます。1 つの名前に HTTPS レコードを複数置くこともできます。解釈できる SvcParam の鍵は次のとおりです。

| 鍵 | 値 | 例 |
| --- | --- | --- |
| `mandatory` | カンマ区切りの鍵名 | `mandatory=alpn,port` |
| `alpn` | カンマ区切りのプロトコル ID | `alpn=h3,h2` |
| `no-default-alpn` | 値なし | `no-default-alpn` |
| `port` | 0〜65535 | `port=8443` |
| `ipv4hint` | カンマ区切りの IPv4 アドレス | `ipv4hint=192.0.2.1,192.0.2.2` |
| `ech` | base64 | `ech=AEX+DQ==` |
| `ipv6hint` | カンマ区切りの IPv6 アドレス | `ipv6hint=2001:db8::1` |
| `dohpath` | URI テンプレート | `dohpath=/dns-query{?dns}` |
| `keyNNNN` | 任意の値。上の鍵の番号ならその鍵の形で読む | `key65000=opaque` |

値は引用符で囲んでも構いません（`alpn="h3,h2"`）。バックスラッシュによるエスケープは解釈せず、エラーにします。表に無い鍵名もエラーです。

鍵は 1 回だけ書いてください。名前と `keyNNNN` の両方で同じ鍵を書いたとき（`dohpath=… key7=…`）は拒否します。ただし、同じ鍵名を 2 回書いたとき（`port=443 port=8443`）は検出できません。パーサが黙ってあとの値を残すためです。

## シリアル

ゾーンを変えるたびに SOA のシリアルを上げてください。`YYYYMMDDnn` の形にしておくと便利です。`SIGHUP` を受けたときの動きは次のとおりです。

- シリアルが新しくなっていれば、ゾーンを差し替えます。
- シリアルも中身も同じなら、何もしません。
- シリアルが同じで中身が違う、またはシリアルが古いときは拒否し、それまでのゾーンで答え続けます。

シリアルは RFC 1982 のシリアル算術で比べるので、一周して小さな値に戻っても構いません。

## 変更を確かめる

```sh
dohyo --config /etc/dohyo/dohyo.yml --check
```

成功すれば原点とシリアルを出します。失敗すれば、ファイル名とどの検査に引っかかったかを出します。`systemctl reload dohyo` の前に実行してください。
